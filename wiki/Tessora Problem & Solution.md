# Tessora Problem & Solution

Part of [[Tessora - Overview]].

## The Problem

Philippine companies with large document footprints (BPOs, conglomerates, logistics, manufacturing, real estate) run on:

- **Scattered storage** — Google Drive folders, shared drives, and email threads with no central system
- **Hidden relationships** — connections between documents exist only in people's heads; no system links contracts to policies to reports
- **Manual search waste** — HR, admin, and compliance teams hunt for the "latest" policy or contract instead of retrieving it instantly
- **No cross-document visibility** — executives can't see patterns, risks, or contradictions across departments without someone manually compiling a report

Existing enterprise RAG tools (Glean, Microsoft Copilot for SharePoint, Notion AI) solve pieces of this — but they're priced in USD, built for US/EU compliance norms, and not localized for Philippine business practices, the Data Privacy Act (RA 10173), or English-Filipino-Taglish document mixing. That gap is Tessora's opening.

## The Solution

A shared knowledge base where:

1. **Automatic ingestion** — documents are parsed, indexed, and embedded (contracts, SOPs, reports, policies, emails)
2. **Grounded Q&A** — natural-language queries return answers with source citations, powered by RAG
3. **Auto-mapped relationships** — a graph of how contracts, policies, and reports connect, generated from content, not manual linking
4. **Permission-safe retrieval** — everything filtered by role, so sensitive documents only surface to authorized users

See [[Tessora Services]] for the two-tier service model.
